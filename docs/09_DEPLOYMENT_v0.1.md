# 佈署與分享 v0.1

日期:2026-09-16  狀態:提案,待 YC 確認  依據:00_PROJECT D-12(主架構維持 Chromium 外掛 + 獨立 HTML 手動模式;動機 = 院內 IT 政策風險、他院好裝)
取代:01_ARCHITECTURE §6 第 7 項「佈署方式」

## 0. 一句話

外掛上 Chrome Web Store(先未列出、院內試用後公開),院內 IT 用政策放行或派送;規則照舊從 GitHub Pages 抓;同一份程式另打包成一頁「手動模式」放 GitHub Pages,給裝不了外掛的人與他院試用。

## 1. 院內佈署三條路

- 未封裝載入(現況):要開發人員模式、每台手動、更新要重載;IT 政策一收緊就全滅。只適合試用期。
- Web Store(未列出 unlisted → 公開):一個連結安裝、自動更新;Edge 也裝得到(允許來自其他存放區);IT 可用 `ExtensionInstallAllowlist` 放行或 `ExtensionInstallForcelist` 派送。代價是商店審查。
- 企業政策自架更新:IT 派送 + 自架 `update_url`,不經商店;適合院方不願公開時,但 IT 要長期維護派送。

建議路徑:未列出 → 兩院試用 → 公開(與開源同步)。
現況(2026-09-28):v0.4.12 起以 GitHub Release 發行未封裝 zip(院內正式版,流程見 README「發行」);商店未列出待帳號名義決定後再做。
userscript 包裝不列為備案:若 GPO 封鎖全部擴充功能,Tampermonkey 也一起被封;若是允許清單制,加本外掛 ID 與加 Tampermonkey 是同一件事。

## 2. 商店審查要準備的

- 權限說明,每項一句用途:`storage`(規則快取、工作站設定)、`medcloud2.nhi.gov.tw`(讀取雲端資料)、NIIS 主機(讀取接種史)、`*.github.io`(下載規則)。
- 隱私政策頁(放 GitHub Pages):病患資料只在瀏覽器記憶體與 session storage;唯一對外連線是下載規則;不收集任何統計或識別資料。
- MV3 禁止遠端程式碼。本專案規則是資料、引擎是解譯器(rules/EXECUTION.md)→ 合規;這正是「YAML 不翻譯成程式碼」設計的回報。
- NIIS 主機固定 `10.241.219.35`(YC 確認全台同一台),維持一般 `host_permissions`,不做可選授權。
- 需要真正的選項頁(取代 console 設定):管轄(06)、自動點擊讀卡、釘住規則版本、隱私政策連結。
- 發佈流程:GitHub Actions 建置 zip + 版本號 + 內建當時的規則檔 → 上傳商店(人工或商店 API)。外掛版本與規則版本分開演進:規則天天可變,外掛幾個月一版。

## 3. 要問資訊室的三個問題

1. 院內 Chrome / Edge 是否有 GPO 封鎖擴充功能(`ExtensionInstallBlocklist`)?若有,能否把本外掛 ID 加入允許清單?
2. 門診電腦能否連 `*.github.io`?不能的話,備案是 IT 派送規則檔或院內鏡像(D-07 備案)。
3. 院內資安(ISMS)對「存取健保雲端的第三方外掛」有無審查程序?要哪些文件(資料流圖、權限清單、原始碼)?

第三題不只院內:健保署對第三方軟體存取雲端系統的規範也要確認一次。我不確定現行規定,列為待驗,不猜。

## 4. 獨立 HTML 手動模式(附屬,不是第二個產品)

- 同一份引擎與面板打包成單一 HTML,放 GitHub Pages;規則與外掛同來源、同版本。
- 輸入兩種:貼上外掛的「匯出診斷 JSON」(FHIR Bundle);或手動表單——生日、性別、人工條件勾選、接種史列表(疫苗碼、日期、公費/自費)。
- 輸出同一個結果面板;可選 archived 規則集 + 檢核日做回溯(07 §5 的 `eval` 圖形版)。
- 不做:伺服器、上傳、HIS、統計。純靜態,關頁即清。
- 用途:他院與衛生局示範;外掛裝不了時的備援(醫師自己看雲端、手填事實);規則變更 PR 的人讀預覽。
- 護欄:功能永遠是外掛面板的子集;不因它長出「疫苗諮詢系統」。

## 5. 他院採用清單

- 安裝:商店連結 → 選項頁設管轄 → 插卡試一次。

- 支援:GitHub Issues;不承諾服務水準。
