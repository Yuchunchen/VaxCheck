## IMUE0190 特殊給付限制 `GET imue0190/imue0190s01/lftp-data`
```
{ log2time, robject: { drugs: [...], medical_service: [...], special_material: [...] } }
```
drugs 每筆:
```
cure_cname (項目中文名, 長字串)  cure_path / cure_path_name (null)
data_source ("申報")  data_type ("2")
drug_atc7_code (null!)  func_date ("YYYY-MM-DDTHH:MM:SS")
hosp ("門診")  hosp_abbr  hosp_id (10 碼)
icd_cname (null)  icd_code (5 碼無點)
order_code (10 碼健保代碼)  order_drug_day (number)  order_qty (number)
pdt_model (null)
```
- 病患 1:drugs 9 筆(2 種 order_code)、medical_service 0、special_material 0
- 推測 data_type:1=醫療服務 2=藥品 3=特材(待驗)
- lftp 的藥品沒有 ATC → 免疫抑制劑判定仍走 IMUE0008(有 drug_atc7_code);lftp 主要價值在 special_material(人工電子耳)與 medical_service

## IMUE0180 B/C 肝專區 `GET imue0180/imue0180s01/hbcv-data`
```
{ log2time, robject: {
  health_data: [],  med_data: [],
  img_data: { title1, title2 },
  medical_data: { func_date, hosp, icd_name },
  inspection_data: [{ data_src, drug_ename, exam_item, exe_s_date, exe_e_date, func_date, func_type_name, hosp, icd_cname, inspection_type, order_code, order_qty }],
  result_data: [{ assay_item_name, assay_method, assay_value, case_time, consult_value, data_src, func_type_name, hosp, icd_cname, inspect_mode, order_code, order_name, real_inspect_date, recipe_date, result_type }],
  screening_data: [{ item, memo, result }]
} }
```
- 對疫苗檢核:HBsAg/anti-HBs 在 result_data;若做 B 肝疫苗規則可用

## NIIS 院所版結果頁(PostBack 後,同一 URL)
```
div#div_result > section.tabs >
  span.tabItem(.active) "預防接種紀錄" + div.tabContent > div.dataTb > table   ← 全部紀錄
  span.tabItem "肺炎鏈球菌"  + div.tabContent > … > table
  span.tabItem "COVID-19"    + div.tabContent > … > table
  span.tabItem "流感疫苗"     + div.tabContent > … > table
  span.tabItem "M痘/HPV"      + div.tabContent > … > table
```
- table 無 thead;第一列 td/th 為表頭:`序號 | 劑別代號 | 疫苗中文名稱 | 接種日 | 批號類型 | 接種單位`
- 查無資料:表頭列 + 一列單格 `本個案查無接種紀錄`
- 接種日:7 碼民國 `YYYMMDD`
- 劑別代號:`Flu-1`、`CoV_AZ-1(批號D006A)` → 可能夾批號;**格式 = 官方 VaccID-劑次**(2026-09-17 由 CDC API 規格書確認,見 rules/NIIS_CODES.md)
- 批號類型:`公費`(官方另有 自費、臨床試驗)
- 表頭 `tb_RocID` PostBack 後仍有值 → 身分核對可行
- 表格可排序(sortTableByColumns)→ 解析時不可依賴列順序,要用日期排序

## NIIS 查詢頁讀卡機制(依 2026-09-28 院內存檔;只記結構,疾管署 JS 原檔不進 repo)
- 查詢頁 = 根網址 `https://10.241.219.35/`;表單 POST 回根網址(ASP.NET PostBack),無登入頁、無轉址。
- 關鍵元素:
  - `#btn_Query`:「讀取健保卡及醫事人員卡」,`type=submit`,`onclick="return CheckInput();"`
  - `#tb_RocID`、`#tb_bd`:隱藏欄位,讀卡後由頁面程式填入(外掛不可預填)
  - `#cb_reader`:「使用健保IC卡讀卡機」,預設勾選
  - `#div_result`:查詢結果容器(結構見上方「NIIS 院所版結果頁」)
- `CheckInput()` 依序呼叫 `ReadHPCCard()`(醫事人員卡)與 `ReadHCCard()`(健保卡),經 ServiSign 本機服務 `https://localhost:56367`(備援 56387、56407)以**同步 XHR** 讀卡,讀完才送出表單 → 讀卡期間頁面主執行緒被阻塞。
- 簽章與 PIN 相關程式碼已被註解 → 推定查詢不需 PIN(待院內確認,TESTING W4)。
- **讀卡失敗只跳 alert,`CheckInput` 仍回傳 true** → `#tb_RocID` 為空也會送出表單;伺服器可能回「本個案查無接種紀錄」。外掛因此把「身分為空的查無」視為 `error/niis_no_identity`(v0.4.9),不當 0 筆。
- 推測(未驗):PostBack 會保留 ViewState,讀卡失敗時隱藏欄位可能殘留前一位的身分證 → 查到前一位病患;外掛的身分雜湊比對會以「身分不符」擋下。外掛換病患時以 GET 導回根網址,可清掉舊狀態。
- 外掛代按方式:content script 執行 `document.querySelector('#btn_Query').click()`;inline onclick 在頁面環境執行,同步讀卡後送出。
